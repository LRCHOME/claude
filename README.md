# Claude provider launchers

Четыре команды для запуска установленного Claude Code с другим провайдером:

| Команда | Подключение | Что требуется от пользователя |
| --- | --- | --- |
| `gpt_claude` | Claude Code → локальный адаптер → OpenAI Responses API | Своя подписка ChatGPT с доступом к Sign in with ChatGPT / token sharing |
| `ds_claude` | Claude Code → DeepSeek напрямую | Свой API-ключ DeepSeek |
| `or_claude` | Claude Code → OpenRouter напрямую | Свой API-ключ OpenRouter и выбранная модель |
| `ai_claude` | Claude Code → ваш Anthropic-совместимый endpoint напрямую | URL сервера, API-ключ и ID модели |

Лаунчеры сохраняют текущую рабочую папку, передают аргументы Claude Code и задают
провайдера только дочернему процессу. `ds_claude`, `or_claude` и `ai_claude`
работают напрямую, без GPT-адаптера. Глобальные настройки Claude не переписываются.

Это сторонняя интеграция. Совместимость с новыми версиями Claude Code и моделями
нужно проверять; наличие подписки ChatGPT само по себе не гарантирует доступ
к token sharing. Автоматического перехода на платный OpenAI API key нет.

## Требования

- Установленный нативный Claude Code: команда `claude` на macOS/Linux,
  `claude.exe` на Windows.
- Node.js **20.18.1 или новее** и npm для `gpt_claude`.
- Python **3.10 или новее** для `ds_claude`, `or_claude`, `ai_claude` и установщика macOS/Linux.
- Git для клонирования репозитория.

На Windows 10/11 зависимости ниже может поставить `install-windows.ps1`,
на Linux — `install-linux.sh`. Нужен доступ в интернет. Если WinGet отсутствует
или не работает, установщик зарегистрирует App Installer для текущего пользователя,
а при необходимости установит стабильный WinGet через официальный модуль
`Microsoft.WinGet.Client` из PowerShell Gallery. Используется
[рекомендованный Microsoft способ](https://learn.microsoft.com/en-us/windows/package-manager/winget/troubleshooting).
Когда WinGet недоступен, недостающие компоненты ставятся официальными установщиками
напрямую. На Linux установщик работает без root и сам ставит Node.js и Claude Code.
Если Git ещё не установлен, скачайте репозиторий через **Code → Download ZIP**,
распакуйте его и запустите установщик из полученной папки.

```sh
git clone https://github.com/lrchome/claude.git
cd claude
npm ci
```

Для использования только `ds_claude`, `or_claude` и `ai_claude` установка Node.js-зависимостей
не требуется. Их Windows-обёртки используют команду `python`, Unix-обёртки — `python3`.

## Установка команд на Windows

В PowerShell из папки репозитория:

```powershell
powershell -NoProfile -File .\install-windows.ps1
```

Установщик проверит имеющиеся программы и через WinGet поставит недостающие
или неподходящие по версии. WinGet >=1.8 устанавливается только при первой
необходимости установить пакет; если все программы уже подходят, WinGet не требуется.
Если WinGet поставить не удалось (например, App Installer не зарегистрирован),
установщик не останавливается и ставит нужные компоненты официальными
установщиками напрямую — см. ниже.

| Компонент | Пакет WinGet |
| --- | --- |
| Node.js LTS с npm | `OpenJS.NodeJS.LTS` |
| Python 3.14 для всех пользователей | `Python.Python.3.14`, `--scope machine` |
| Git for Windows | `Git.Git` |
| Нативный Claude Code для текущего пользователя | `Anthropic.ClaudeCode` |

Подходящие существующие Node.js >=20.18.1 и системный Python >=3.10 сохраняются.
Python всегда устанавливается для всех пользователей. Для его обнаружения проверяются
регистрации HKLM и каталоги Program Files, включая системную установку в нестандартной папке.
Для Python, Node.js или Git Windows может запросить разрешение администратора (UAC).
Если журнал старой попытки Python показывает `core_JustForMe` и `InstallAllUsers=0`,
обновите установщик: текущая версия выбирает системную установку (`InstallAllUsers=1`).
Установщик принимает соглашения выбранных пакетов WinGet. Для установки самого
WinGet нужен доступ к PowerShell Gallery и серверам загрузки Microsoft/GitHub;
заранее установленный Microsoft Store не требуется. NuGet-провайдер и модуль
`Microsoft.WinGet.Client` при необходимости устанавливаются для текущего пользователя.
Если восстановление WinGet требует `-AllUsers`, установщик предложит UAC и повторит
только восстановление WinGet с правами администратора. Затем App Installer снова
регистрируется для исходного пользователя, и установка продолжается в его сеансе.
В уже открытом окне администратора сразу применяется `Repair-WinGetPackageManager -AllUsers`.
Если политика Windows или сеть блокирует установку WinGet, установщик пишет причину
и переходит к прямым установщикам. Повторно WinGet в этом запуске уже не пробуется:

| Компонент | Что скачивается |
| --- | --- |
| Node.js LTS с npm | официальный MSI с nodejs.org, последний LTS >=20.18.1 |
| Python 3.14 для всех пользователей | `python-3.14.x-amd64.exe` с python.org, `InstallAllUsers=1` |
| Git for Windows | `Git-*-64-bit.exe` из последнего релиза git-for-windows/git на GitHub |
| Нативный Claude Code | официальный скрипт `downloads.claude.ai/claude-code-releases/bootstrap.ps1` (запасной адрес `claude.ai/install.ps1`), для текущего пользователя |

Подлинность скачанных EXE и MSI проверяется по подписи Authenticode; при
недействительной подписи установка этого компонента прекращается с указанием файла.
Скрипт Claude проверяется на содержимое: если сервер отдал HTML-страницу вместо
PowerShell, установщик пробует второй адрес и сообщает обе причины.
Для установки Node.js, Python и Git появится запрос UAC; Claude Code ставится
без прав администратора. Если и прямая установка не удалась, выводится причина
обеих попыток. Скачанные файлы удаляются из временного каталога после установки.
Политика выполнения PowerShell не меняется и не обходится установщиком.

После установки обновится PATH текущего процесса, поэтому продолжить можно
в том же окне. Установщик при необходимости выполнит `npm ci`,
затем проверит все три обёртки по абсолютным путям. Каталог
`bin` добавляется в пользовательский PATH только после успешных проверок.
В PATH также добавляются каталоги проверенных программ.
При ошибке выводится исходное сообщение процесса, а не только код выхода.
Сначала выполните настройку провайдеров ниже, затем используйте
соответствующий лаунчер. Перезапустите терминал после установки.

Для диагностики без установки зависимостей и изменения постоянного PATH
(в этом режиме WinGet также не устанавливается и App Installer не регистрируется):

```powershell
powershell -NoProfile -File .\install-windows.ps1 -CheckOnly
```

Если старая версия установщика завершалась сообщением
`Failed to repair winget. Try running with -AllUsers in administrator mode`,
обновите репозиторий и запустите установку снова, подтвердив UAC.
Если Git ещё отсутствует, в папке репозитория можно обновить только установщик:

```powershell
Invoke-WebRequest -UseBasicParsing 'https://raw.githubusercontent.com/lrchome/claude/main/install-windows.ps1' -OutFile .\install-windows.ps1
powershell -NoProfile -File .\install-windows.ps1
```

Для отдельного восстановления WinGet откройте PowerShell **от имени администратора**
и выполните из папки репозитория:

```powershell
powershell -NoProfile -File .\install-windows.ps1 -RepairWinGetAllUsers
```

Этот режим чинит только WinGet. После него повторите обычную установку из окна
первоначального пользователя. Если UAC отклонён или восстановление не удалось,
установщик остановится и покажет исходную ошибку и результат повторной попытки.

Если Python или другая программа не устанавливается с **1625** или WinGet
**-1978334961 / 0x8A15010F**, Windows запрещает установку политикой.
[Описание кода Microsoft](https://learn.microsoft.com/en-us/windows/win32/msi/error-codes).
Установщик покажет понятную причину, сохранит исходный вывод и остановит установку.
Вывод WinGet читается как UTF-8, в том числе в Windows PowerShell 5.1.

Для уточнения причины нужен журнал, путь к которому напечатан в ошибке.
Например, последние 80 строк последнего основного журнала Python можно получить так:

```powershell
$logDirectory = Join-Path $env:LOCALAPPDATA 'Packages\Microsoft.DesktopAppInstaller_8wekyb3d8bbwe\LocalState\DiagOutputDir'
$pythonLog = Get-ChildItem -LiteralPath $logDirectory -Filter 'Python.Python.*.log' | Sort-Object LastWriteTime -Descending | Select-Object -First 1
if ($pythonLog) { Get-Content -LiteralPath $pythonLog.FullName -Tail 80 }
```

По одному коду нельзя определить, запрещён ли весь Python, отдельный компонент
или установка для текущего пользователя. Передайте журнал администратору компьютера,
чтобы он разрешил подходящий способ установки. После установки разрешённого
системного Python >=3.10 повторите запуск `install-windows.ps1`: он обнаружит готовый Python.

Если раньше установка завершалась `gpt_claude --version failed: 1`, обновите
репозиторий и повторите установку. Теперь `--version` и `--help` передаются
нативному Claude без загрузки GPT-модулей, npm-зависимостей или авторизации.
Для реальных запросов зависимость `undici` по-прежнему обязательна; сообщение
об её отсутствии содержит команду `npm ci` и путь к репозиторию.

Если локальная политика PowerShell запрещает запуск скриптов, команды доступны
и без установщика по полному пути:

```powershell
.\bin\gpt_claude.cmd --version
.\bin\ds_claude.cmd --version
.\bin\or_claude.cmd --version
.\bin\ai_claude.cmd --version
```

Для этого зависимости уже должны быть установлены. Если политика запрещает
сам установщик, согласуйте разрешённый способ запуска с администратором;
`install-windows.ps1` не изменяет политику. Ключи API и вход в аккаунт
настраиваются отдельно после установки.

## Установка команд на macOS / Linux

### Linux

Полный установщик работает без root: проверяет Python 3.10+, при необходимости
скачивает официальный Node.js LTS (сверяя SHA256), ставит Claude Code официальным
скриптом, выполняет `npm ci` и создаёт все четыре обёртки.

```sh
bash install-linux.sh
bash install-linux.sh --check-only   # только проверка, ничего не менять
```

Подробная инструкция: [INSTALL-LINUX.md](INSTALL-LINUX.md).

### macOS

```sh
python3 install-unix.py
export PATH="$HOME/.local/bin:$PATH"
gpt_claude --version
```

Для постоянного PATH добавьте `export PATH="$HOME/.local/bin:$PATH"` в файл
конфигурации своего shell, например `~/.zshrc` для стандартного zsh на Mac.
Установщик создаёт обёртки в `~/.local/bin`, заменяя прежние обёртки с такими
именами. Если переместили репозиторий, запустите установщик заново.
Подробная инструкция: [INSTALL-MAC.md](INSTALL-MAC.md).

## Claude Desktop через DeepSeek (неофициально)

Приложение Claude Desktop умеет работать через сторонний шлюз в режиме
**Third-Party Inference**. Для DeepSeek в комплекте есть локальный шлюз
`desktop_gateway.py`: он отдаёт приложению Claude-модели, подменяет их на
`deepseek-v4-pro` / `deepseek-flash` и проксирует запросы в DeepSeek,
сохраняя стриминг и tool calls.

```powershell
claude_gateway            # Windows, из bin/
python3 desktop_gateway.py  # Linux/macOS
```

Anthropic не поддерживает маршрутизацию на не-Claude модели, поэтому это
экспериментальный сценарий. Настройка окна Third-Party Inference, флаги шлюза,
диагностика и ограничения: [INSTALL-DESKTOP-3P.md](INSTALL-DESKTOP-3P.md).

## Настройка gpt_claude

Вставлять API-ключ OpenAI не требуется. Войдите **в свой аккаунт** через браузер:

```sh
gpt_claude --login
gpt_claude --launcher-info
gpt_claude --models
```

Если браузер не открылся, используйте ссылку из терминала. Вход отдельный:
авторизация Codex и Claude автоматически не переносится. Лаунчер создаёт свои
`auth.json` и `host.json` в `~/.config/gpt_claude` вне репозитория
(`%USERPROFILE%\.config\gpt_claude` на Windows). Не копируйте эти файлы другим людям.

```sh
cd /path/to/your/project
gpt_claude
gpt_claude --resume
```

По умолчанию выбирается `gpt-6.2-sol` со средним уровнем рассуждения (`medium`),
если модель есть в каталоге аккаунта; иначе первая доступная.
Переменные ниже позволяют переопределить эти значения. Выбирайте ID из вывода `--models`.

PowerShell:

```powershell
$env:GPT_CLAUDE_MODEL = 'gpt-6.2-sol'
$env:GPT_CLAUDE_EFFORT = 'medium'
gpt_claude
```

macOS/Linux:

```sh
GPT_CLAUDE_MODEL=gpt-6.2-sol GPT_CLAUDE_EFFORT=medium gpt_claude
```

Допустимые уровни reasoning зависят от модели. Значение `default` отключает
явную передачу уровня в API. Выбор через `GPT_CLAUDE_EFFORT` относится к адаптеру;
нативная команда `/effort` Claude не заменяет эту переменную.

## Настройка ds_claude, or_claude и ai_claude

Если нужен только DeepSeek на новом компьютере, файл OpenCode не обязателен:
при отсутствии стандартного `~/.config/opencode/opencode.json` достаточно задать
`DEEPSEEK_API_KEY`. В PowerShell ключ можно ввести скрыто:

```powershell
$env:DEEPSEEK_API_KEY = [System.Net.NetworkCredential]::new('', (Read-Host 'API-ключ DeepSeek' -AsSecureString)).Password
ds_claude --launcher-info
ds_claude
```

Переменная действует в текущем терминале. Если задан `OPENCODE_CONFIG`, этот файл
имеет приоритет и должен существовать. Существующая стандартная конфигурация также
имеет приоритет; ключ в ней не заменяется значением окружения автоматически.
Для `ai_claude` и настройки через файл используйте следующие шаги.

### 1. Скопируйте пример в личную конфигурацию

По умолчанию читается `~/.config/opencode/opencode.json`. Если вы уже используете
OpenCode, сохраните существующие настройки и добавьте нужный provider в них.
Либо используйте отдельный файл, как в примере ниже.

PowerShell из папки репозитория:

```powershell
$providerDirectory = Join-Path $HOME '.config\claude-launchers'
New-Item -ItemType Directory -Path $providerDirectory -Force
$env:OPENCODE_CONFIG = Join-Path $providerDirectory 'providers.json'
if (-not (Test-Path -LiteralPath $env:OPENCODE_CONFIG)) {
    Copy-Item .\examples\opencode.json $env:OPENCODE_CONFIG
}
notepad $env:OPENCODE_CONFIG
```

macOS/Linux:

```sh
mkdir -p "$HOME/.config/claude-launchers"
export OPENCODE_CONFIG="$HOME/.config/claude-launchers/providers.json"
if [ ! -f "$OPENCODE_CONFIG" ]; then
  cp examples/opencode.json "$OPENCODE_CONFIG"
fi
chmod 600 "$OPENCODE_CONFIG"
```

Откройте скопированный файл в своём редакторе. Пример находится вне репозитория,
поэтому введённые в него значения не попадут в коммит этого проекта.
`OPENCODE_CONFIG` необходимо задавать в каждом новом терминале или сохранить
её в настройках окружения своей ОС/shell.

### 2. Укажите свои значения

| Где | Что вставить |
| --- | --- |
| Переменная `DEEPSEEK_API_KEY` | Ваш API-ключ DeepSeek; для запуска только GPT или AI не нужен |
| Переменная `OPENROUTER_API_KEY` | Ваш API-ключ OpenRouter; нужен только `or_claude` |
| Переменная `AI_CLAUDE_BASE_URL` | URL вашего Anthropic-совместимого сервера, например `https://provider.example` |
| Переменная `AI_CLAUDE_API_KEY` | Ваш ключ этого сервера |
| `provider.ai-lrcs.models.local.id` в скопированном JSON | Замените `YOUR_MODEL_ID` на настоящий ID модели сервера |
| `limit.context` / `limit.output` | Реальные лимиты выбранной модели в токенах |

PowerShell (значения только для текущего терминала):

```powershell
$env:DEEPSEEK_API_KEY = Read-Host 'Ваш API-ключ DeepSeek'
$env:AI_CLAUDE_BASE_URL = Read-Host 'URL вашего Anthropic-совместимого сервера'
$env:AI_CLAUDE_API_KEY = Read-Host 'Ваш API-ключ AI-сервера'
```

macOS/Linux:

```sh
export DEEPSEEK_API_KEY='YOUR_DEEPSEEK_KEY'
export AI_CLAUDE_BASE_URL='https://provider.example'
export AI_CLAUDE_API_KEY='YOUR_AI_KEY'
```

Для выбранного лаунчера нужны только его настройки. Слова `YOUR_…` и домен
`provider.example` — заглушки, их необходимо заменить. Лаунчер не загружает
`.env` автоматически. Значения ключей не передаются аргументами командной строки.

В примере JSON ключи задаются ссылками `{env:NAME}`. Поддерживается также
`{file:/absolute/path/to/key}`: сохраните ключ в личном файле вне репозитория
и укажите ссылку в поле `apiKey`. Относительные пути считаются от каталога
конфигурации. JSON и файлы ключей читаются как UTF-8, включая BOM.

`ds_claude` использует provider `deepseek`, модель с ключом `deepseek-flash`
и endpoint `https://api.deepseek.com/anthropic`. Проверьте доступность этого
ID в своём аккаунте; при необходимости измените поле `id` в личном JSON.
Для основной модели, подагентов и быстрых задач выбирается Flash. Лаунчер
задаёт `CLAUDE_CODE_EFFORT_LEVEL=medium`. По [правилам DeepSeek](https://api-docs.deepseek.com/guides/thinking_mode/)
запрошенный `medium` сопоставляется с фактическим `high` на сервере.
Если обновляете старую конфигурацию, добавьте запись `deepseek-flash`
в `provider.deepseek.models`, как в [примере](examples/opencode.json).

`or_claude` использует provider `openrouter` и Anthropic-совместимый endpoint
`https://openrouter.ai/api`. Модель задаётся командой `or_claude --setmodel <id>`
или переменной `OR_CLAUDE_MODEL`: без явного выбора лаунчер не запускается,
чтобы не отправлять задачи случайной модели. ID берите из `or_claude --listmodels`.
Если каталог моделей отвечает HTTP 403, доступ к `openrouter.ai` блокирует сеть
или прокси, а не обязательно ключ.

`ai_claude` использует provider с историческим именем `ai-lrcs` и модель
с ключом `local`. Значения `baseURL` и `id` настраиваются пользователем;
название provider в конфигурации оставьте таким, как в примере.
Сервер должен поддерживать Anthropic Messages API, а не только OpenAI Chat Completions.
Конечный `/v1` в `baseURL` удаляется, поскольку Claude добавляет `/v1/messages` сам.

Если provider `ai-lrcs` отсутствует в OpenCode-конфигурации, `ai_claude` читает
его из `~/.pi/agent/models.json` (или `PI_MODELS_CONFIG`). Формат показан
в [examples/pi-models.json](examples/pi-models.json). Файл OpenCode при этом
всё равно должен существовать и содержать корректный JSON, хотя бы `{}`.
В pi-варианте ищется модель с `id: "local"`; для произвольного ID модели
используйте основной OpenCode-формат с отдельным полем `id`.

### 3. Ключ, модели и выбор модели

`ds_claude` и `or_claude` хранят ключ и выбранную модель сами:

```sh
ds_claude --setkey           # скрытый ввод; ключ пишется в provider.deepseek.options.apiKey
or_claude --setkey           # то же для provider.openrouter
ds_claude --listmodels        # модели провайдера, текущая помечена звёздочкой
or_claude --listmodels claude # фильтр по подстроке
ds_claude --setmodel deepseek-v4-pro
```

`--setkey` пишет ключ в файл из `OPENCODE_CONFIG` или в `~/.config/opencode/opencode.json`,
создавая файл при необходимости, и сохраняет остальные настройки. Если сервер
отвечает HTTP 401, ключ не сохраняется. Для скриптов есть `--setkey --stdin`
(ключ из stdin) и `--setkey --from-env` (из `DEEPSEEK_API_KEY`/`OPENROUTER_API_KEY`).
Ключ не передаётся аргументом командной строки и не печатается.

Выбранная модель хранится отдельно, в `~/.config/claude-launchers/state.json`
(или `CLAUDE_LAUNCHERS_STATE`), и не меняет модель OpenCode. `--setmodel` сверяет
ID со списком провайдера и подсказывает похожие, `--force` сохраняет всё равно.
Переменные `DS_CLAUDE_MODEL` и `OR_CLAUDE_MODEL` перекрывают сохранённый выбор
в текущем терминале. Если сервер моделей недоступен, `--listmodels` показывает
модели из конфигурации.

### 4. Проверьте и запустите

```sh
ds_claude --launcher-info
or_claude --launcher-info
ai_claude --launcher-info
```

Команды показывают выбранный endpoint и модель без API-ключа. Затем перейдите
в папку рабочего проекта и запустите нужный лаунчер:

```sh
ds_claude
or_claude
ai_claude
```

## Сбои и длительные задачи GPT

GPT-адаптер делает до трёх попыток при временных ошибках, обрыве или таймауте.
Для таймаутов действует дополнительный общий бюджет: два зависания одного
неизменённого запроса, включая новые повторы со стороны Claude. После исчерпания
бюджета этот запрос не отправляется в OpenAI повторно в течение 10 минут.
Ошибка передаётся как `504 timeout_error` с `x-should-retry: false` до начала SSE;
в начатом потоке — SSE `timeout_error`. Это предотвращает умножение повторов
адаптера на повторы клиента во время зависшего сжатия истории. Изменённый запрос
имеет отдельный бюджет; перезапуск процесса очищает локальное состояние защиты.
Закрытие запроса клиентом после минуты ожидания также учитывается в бюджете:
так выглядят, в частности, нативные клиентские таймауты. Быстрый `Esc` не считается
зависанием. По умолчанию лаунчер задаёт `CLAUDE_CODE_MAX_RETRIES=0`, поскольку
сетевые повторы выполняет адаптер, и увеличивает `API_TIMEOUT_MS` до предела
попытки адаптера плюс минута. Явно заданные пользователем значения этих двух
переменных сохраняются. Это ограничение повторов не гарантирует, что интерфейс
Claude сможет автоматически завершить уже зависшее автосжатие: в таком случае
прервите запуск и продолжите в новой сессии по сохранённым артефактам проекта.
По умолчанию отсутствие сетевых данных OpenAI в течение 300 секунд прерывает
попытку. Служебные SSE-комментарии и части ещё не завершённого события считаются
сетевой активностью: ожидание не прерывается только из-за отсутствия готового JSON.
Отдельный предел в 15 минут на попытку не позволяет бесконечным keepalive-сообщениям
удерживать зависший запрос. Эти ограничения относятся к запросу, а не ко всей задаче.

| Переменная | Значение по умолчанию | Назначение |
| --- | --- | --- |
| `GPT_CLAUDE_MODEL` | `gpt-6.2-sol`, если доступна | Модель на весь запуск |
| `GPT_CLAUDE_EFFORT` | `medium` | Уровень reasoning |
| `GPT_CLAUDE_IDLE_TIMEOUT_MS` | `300000` | Таймаут отсутствия сетевых данных, миллисекунды |
| `GPT_CLAUDE_RESPONSE_TIMEOUT_MS` | `900000` | Общий предел времени одной попытки, миллисекунды |
| `GPT_CLAUDE_DEBUG` | Выключено | `1` включает сообщения о завершённых запросах |
| `GPT_CLAUDE_LOGGING` | Включено | `0` отключает сохранение метаданных запросов |
| `GPT_CLAUDE_STALL_LIMIT` | `2` | Общий бюджет таймаутов одного неизменённого запроса |

Таймаут можно задать явно (в примере пять минут без сетевых данных):

```powershell
$env:GPT_CLAUDE_IDLE_TIMEOUT_MS = '300000'
$env:GPT_CLAUDE_DEBUG = '1'
gpt_claude --resume
```

```sh
GPT_CLAUDE_IDLE_TIMEOUT_MS=300000 GPT_CLAUDE_DEBUG=1 gpt_claude --resume
```

Перегрузка передаётся Claude как `529 overloaded_error` или SSE-ошибка этого типа
в уже начатом потоке. Ограничение частоты запросов остаётся `rate_limit_error`.
Повторы учитывают `Retry-After`; интервалы более 30 секунд передаются клиенту
без раннего внутреннего повтора. В начатом SSE интервал остаётся в сообщении
ошибки, поскольку HTTP-заголовки уже отправлены.

Частичная история параллельных инструментов не восстанавливает вызовы без
результатов из replay. Незавершённые действия отмечаются как имеющие неизвестный
статус, результаты не выдумываются. Повторы GPT-запросов происходят до передачи
вызовов инструментов Claude и сами не выполняют команды пользователя.

Сбои и повторы печатаются всегда. Ошибки включают доступные ID запросов/ответов,
тип, код, параметр и сообщение OpenAI. Запросы целиком не записываются, но сообщение
сервера может содержать фрагмент некорректного значения. Проверяйте журнал
перед публикацией. Не отправляйте `auth.json`, API-ключи или историю сессии целиком.

При запуске `gpt_claude` показывает путь к JSONL-журналу метаданных в
`~/.config/gpt_claude/logs` (`%USERPROFILE%\.config\gpt_claude\logs` на Windows).
Он сохраняет фазу запроса, последний тип SSE-события, ID ответа/запроса,
объём полученных данных, тайминги и коды ошибок. Промпты, заголовки авторизации,
reasoning, аргументы и результаты инструментов, свободный текст ошибки API
в этот файл не записываются. Лимит файла — 5 MiB на процесс; старые файлы
автоматически не удаляются. Ошибка записи журнала не прерывает работу адаптера.
В истории Claude промежуточные сетевые ошибки могут отсутствовать; для их
разбора используйте этот журнал.

В журнале также сохраняются количество SSE-событий, объём текстовых дельт,
число завершённых частей ответа, действующие таймауты и запрошенный клиентом
`max_tokens`. Это числовые счётчики, а не содержимое ответа. API-успех признаётся
только после `response.completed`: частичный текст при обрыве не выдаётся как
завершённое сжатие истории. Пятиминутный таймаут уменьшает ранние повторы
длительных запросов, но не устраняет причину прекращения данных на стороне
сети или сервиса. Параметр `max_output_tokens` на подписочном endpoint не поддерживается.

Готовые элементы из `response.output_item.done` объединяются с итоговым `response.completed`:
если сервер не продублировал их в `response.output`, текст и вызовы инструментов не теряются.
Незавершённые элементы из `response.output_item.added` не исполняются. Ответ без видимого
текста и без вызовов инструментов возвращает ошибку `empty_response`, а не пустой успешный ход.
Событие журнала `response_assembled` содержит только числа элементов в потоке,
в итоговом событии и после объединения; содержимое инструментов туда не попадает.

После изменения кода или переменных окружения перезапустите лаунчер.
Если задача остановилась окончательно, автоматического возобновления всей
задачи нет: восстановите сессию через `--resume` и проверьте состояние инструментов.
Обработка сбоев у прямых `ds_claude`, `or_claude` и `ai_claude` остаётся на стороне Claude Code
и провайдера; параметры `GPT_CLAUDE_*` к ним не относятся.

## Сеть

GPT-адаптер предпочитает HTTP/2 при TLS-соединении с OpenAI, в том числе внутри
прокси-туннеля CONNECT. Если сервер не предлагает HTTP/2, ALPN выбирает HTTP/1.1.
Проверка сертификатов остаётся включённой. Это устраняет воспроизведённый обрыв
длинных ответов около 61-й секунды на HTTP/1.1; таймауты и лимиты повторов сохранены.

На Windows GPT-адаптер учитывает системный прокси текущего пользователя,
включая PAC/WPAD и исключения. Явные `HTTP_PROXY`/`HTTPS_PROXY` имеют приоритет,
при этом учитывается `NO_PROXY`. В текущей реализации системный выбор прокси
адаптера реализован только для Windows; на macOS/Linux используется обычный
прямое соединение undici с поддержкой HTTP/2. Локальный обмен с адаптером должен идти напрямую.

Если короткие ответы завершаются, а длинные обрываются без `response.completed`,
проверьте маршрут до OpenAI. Такой обрыв может воспроизводиться и вне адаптера.
Одно лишь увеличение контекста или таймаута не доказывает устранение проблемы.

## Тесты

Офлайн-проверки, без запросов к провайдерам:

```sh
npm test
python -m unittest discover -p 'test_*.py'
```

На Mac используйте `python3` вместо `python`. Сквозные проверки GPT расходуют
токены вашей подписки:

```sh
npm run smoke:gpt
npm run smoke:resume
npm run smoke:partial
npm run smoke:stream
```

Проверка остановки повторов с настоящим Claude Code и искусственно зависающим
локальным сервером (без расхода токенов подписки и выполнения инструментов):

```sh
node smoke-gpt-retry-guard.mjs
```

Первые две читают временные тестовые файлы через настоящий Claude Code.
Проверка `smoke:resume` сохраняет отдельную тестовую сессию. `smoke:partial`
проверяет протокол с искусственным результатом Read и не выполняет инструменты.
Проверка `smoke:stream` запрашивает последовательность 1–2000, проверяет весь ответ
и событие `response.completed`; проектные данные не отправляются. Она проверяет
длительный поток и может занимать несколько минут. Тест согласования HTTP/2 через
прокси и напрямую использует OpenSSL для временного сертификата; при его отсутствии
этот офлайн-тест пропускается. На Windows также распознаётся OpenSSL из Git for Windows.
macOS-установщик проверяется автоматически на генерацию обёрток, но полный
сквозной запуск на Mac ещё не подтверждён. Полноценный ночной прогон не является
частью тестов.

## Ограничения

- Текст GPT отображается после завершения хода модели, без постепенного вывода.
- Подсчёт токенов приблизительный; денежная оценка Claude не отражает расход подписки.
- Tool search GPT-адаптером отключён; неподдерживаемые параметры генерации Claude
  не передаются в OpenAI. Не все функции Claude Code совместимы с другим провайдером.
- Автоматический классификатор разрешений Claude остаётся активным на клиенте;
  это не серверный классификатор Anthropic и не гарантия одинаковых решений.
- В исходниках также сохранён вспомогательный `local_adapter.py` для нормализации
  system-блоков локального сервера. Основные команды его не используют.
